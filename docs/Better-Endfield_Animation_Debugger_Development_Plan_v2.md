# Better-Endfield Animation Debugger 开发计划 V2

更新时间：2026-09-08

本轮范围：实时动画调试、动画运行数据记录与导出。

## 1. 目标与边界

在 Better-Endfield 中提供运行时动画调试窗口，让使用者在运行《明日方舟：终末地》时，能够看清当前角色正在播放哪些动画、处于什么状态、如何混合，并记录操作过程中的变化供事后检查。

本计划依据原文的需求重新划分交付阶段，不展开 Hook 方案、接口调用、代码结构和具体开发过程。原文描述的现有项目能力作为待确认的基础条件，不视为已经验证的实现结果。

### 1.1 本轮交付范围

- 实时查看角色、Animator、状态、活动 Clip 及播放信息。
- 查看 PlayableGraph 状态、可观测的混合关系与权重。
- 开始、停止动画数据记录，查看记录期间的状态与 Clip 变化。
- 导出 JSON、CSV，支持离线检查和比较。
- 提供必要的目标选择、数据有效性提示和性能控制。

### 1.2 不纳入本轮

- UE AnimBP、BlendSpace 或其他 UE 资产的生成与重建辅助。
- 自动推断状态机、转换条件、Direction 或 Speed 参数。
- 动画资产数据库、自动分类与节点推荐。
- 修改动画状态、强制播放、调速或其他动画控制功能。
- 导出动画资产、骨骼姿态、关键帧或视频；本计划中的“记录”指运行时调试数据记录。

## 2. 核心使用场景

| 场景 | 使用者要解决的问题 | 预期结果 |
| --- | --- | --- |
| 待机、移动、攻击、技能 | 当前实际播放了什么 | 同时看到角色、状态和活动 Clip |
| 起步、停止、转向、动作切换 | 切换过程中哪些动画参与了混合 | 看到多个活动 Clip 的时间、权重及其所属关系 |
| 角色切换、模型替换、场景切换 | 当前数据是否仍属于正确对象 | 目标变化清晰可见，旧对象数据不会继续冒充实时数据 |
| 复现一次动画异常 | 异常前后发生了什么变化 | 记录完整操作片段，按时间检查状态与 Clip 变化 |
| 离线对比 | 两次操作的动画表现有何区别 | 导出带时间、对象标识和数据有效性的记录 |

## 3. 实时调试需求

### 3.1 目标选择与识别

- 默认定位当前角色；存在多个候选对象时，提供明确的角色与 Animator 选择。
- 显示目标名称和运行期对象标识，区分同名对象。
- 提供“跟随当前角色”和“固定目标”两种模式，并显示当前模式。
- 跟随模式下切换角色应更新目标；固定目标失效时应提示失效，不能静默切换到其他对象。
- 无目标、对象销毁、数据尚未就绪时显示明确状态。

### 3.2 实时数据清单

| 数据类别 | 必需字段或信息 | 展示要求 |
| --- | --- | --- |
| 角色与 Animator | 名称、运行期对象标识、有效状态 | 明确当前观测对象 |
| Animator 状态 | 当前状态名称或标识；可获取时显示层、过渡及下一状态 | 不可获取的内容明确标为未知或不支持 |
| 活动 Clip | 名称、实例标识、所属层或图路径（可获取时） | 支持多个 Clip，同时保留同一 Clip 的不同播放实例 |
| 播放时间 | 当前时间、动画长度、播放进度 | 时间统一使用秒；区分累计时间与循环内进度 |
| 播放阶段 | 当前状态、过渡情况及 Clip 进度 | 起步、循环、收尾等语义仅在有可靠依据时显示 |
| 播放速度 | 可观测的 Animator 或 Playable 速度 | 标明作用层级；没有依据时不合并为单一“最终速度” |
| Loop | Clip 循环属性及可获取的运行时循环信息 | 区分资源属性与实际播放行为 |
| Blend | Clip、Mixer 输入及层级权重（可获取时） | 标明权重来源和作用范围 |
| PlayableGraph | 图标识、有效性、播放状态、输出与节点关系（可获取时） | 提供概要及可展开的层级视图 |
| 数据质量 | 采样时间、数据来源、有效性、缺失原因 | 区分实时、冻结、过期、不可用 |

### 3.3 混合信息的解释规则

- 活动 Clip 列表是核心交付内容，不能只显示最近创建或最近触发播放的 Clip。
- 区分“对象存在”和“当前参与播放或输出”；无法确认活动状态时明确标注。
- 展示局部输入权重时必须带所属 Mixer、层或路径，避免将不同层级的数值直接比较。
- 不强制所有 Clip 权重合计为 1；无法可靠确定最终贡献时，不显示推算的最终贡献。
- 遇到不可识别的节点或无法读取的部分，保留可用数据，并说明缺口。

### 3.4 调试窗口

游戏内 Overlay 为正式交付入口。Console 可用于早期数据验证和故障诊断，不作为最终界面替代品。

窗口至少包含：

1. **目标区**：角色、Animator、跟随模式和目标有效状态。
2. **状态区**：当前状态、层、过渡信息及更新时间。
3. **活动动画区**：Clip 列表、时间、长度、进度、速度、Loop 和权重。
4. **图与混合区**：PlayableGraph 概要和可展开关系。
5. **记录区**：开始、停止、记录时长、样本数、异常计数和导出入口。

支持打开/关闭窗口、按名称筛选 Clip、冻结/恢复显示。冻结仅暂停界面更新，正在进行的数据记录应继续；界面必须提示冻结状态，避免误读为动画停止。

## 4. 记录与导出需求

### 4.1 记录会话

- 用户主动开始和停止记录，每次生成独立会话。
- 开始时记录会话标识、开始时间、目标模式、采样配置及可获取的游戏/工具版本。
- 会话内同时保留采样序号、相对时间和目标标识，支持按发生顺序还原观测过程。
- 跟随模式下发生目标切换时记录切换事件，并区分切换前后的样本；固定目标丢失时记录缺失区间。
- 显示当前记录状态、持续时间、样本数和占用情况。
- 设置记录时长或容量上限。首版达到上限时自动停止并说明原因，保留已经采集的数据。
- 写入失败、目标失效、采样中断等情况必须可见，不静默丢弃数据。

### 4.2 记录内容

| 类型 | 内容 |
| --- | --- |
| 周期样本 | 当前目标、状态、活动 Clip、时间、长度、速度、Loop、权重及图概要 |
| 变化事件 | 观测到的状态变化、Clip 加入/退出、目标切换、图变化 |
| 质量事件 | 数据不可用、采样间隔异常、丢弃样本、容量限制及停止原因 |
| 会话元信息 | 格式版本、版本信息、采样设置、起止时间、完成状态 |

记录以周期样本为基础，变化事件用于快速定位。由相邻样本识别的事件应标注为“采样间变化”，不声称获得了精确触发时刻；短于采样间隔的动作可能未被捕获，应在记录说明中体现这一限制。

图结构在首次获取和发生变化时保留对应版本，后续样本可以引用该版本，保证离线仍能理解 Clip 的所属关系。

### 4.3 记录查看

- 停止记录后可查看会话概要与按时间排列的事件列表。
- 支持按角色、Animator、Clip 和时间范围筛选。
- 支持选择某个已采集时间点，查看该样本的状态及活动 Clip 明细。
- 缺失区间明确标记，不能使用上一条有效数据填充后伪装为连续观测。
- 首版采用时间列表和样本详情完成查看；图形化时间轴可后续增强，不阻塞核心交付。

### 4.4 导出

| 格式 | 用途 | 要求 |
| --- | --- | --- |
| JSON | 完整保存会话并供后续分析 | 保留层级关系、样本、事件、元信息及数据有效性 |
| CSV | 表格筛选与跨会话比较 | 按“样本 × Clip 播放实例/路径”展开；包含会话、时间、目标和权重来源 |

- 两种格式使用一致的字段含义、时间单位和标识规则，附字段说明及格式版本。
- CSV 配套导出会话元信息和事件；没有活动 Clip 的样本也保留记录，避免形成含义不明的时间空白。
- 未知值使用明确的空值/状态约定，不能用 0、False 或空字符串冒充有效数据。
- 正确处理中文名称、逗号、引号和换行；导出结果显示位置、成功状态或错误原因。
- 文件默认使用独立名称，避免覆盖既有会话。

## 5. 稳定性与性能要求

- 调试模块默认关闭，启用与关闭不改变角色动画行为。
- 界面刷新频率与记录采样频率可分别配置，并显示实际采样情况。
- 对角色切换、模型替换、场景加载、图重建及对象销毁进行有效性处理。
- 记录缓冲、图数据和日志具有明确上限；达到限制时执行可解释的停止或降级行为。
- 关闭窗口不等于停止记录；隐藏窗口后应保留轻量记录提示或等效的可见状态。
- 单个字段或图节点读取失败不应导致整个调试窗口不可用。

以下为建议验收基线，需在 M0 固定测试机器、场景和配置后确认：

| 指标 | 建议目标 |
| --- | --- |
| 界面刷新 | 默认 10 Hz |
| 记录采样 | 默认 30 Hz，提供调整选项，记录实际间隔 |
| 连续运行 | 30 分钟调试并记录，无模块导致的崩溃或持续无界内存增长 |
| 性能影响 | 同场景对照下，启用默认调试与记录后平均帧时间增幅不超过 5% |
| 异常可追踪性 | 采样缺口、截断、自动停止均有可查询记录 |

上述数值是计划目标，不代表已测试结果。性能验收同时保留平均值、P95 帧时间和内存曲线，若目标未达成应明确限制并调整默认配置后复测。

## 6. 里程碑与交付标准

各阶段按完成条件推进；M0 完成后再依据能力缺口估算工期，不在缺乏验证的情况下承诺日期。

| 阶段 | 工作目标 | 交付物 | 退出条件 |
| --- | --- | --- | --- |
| M0：需求与能力确认 | 确认目标识别、字段可用性及测试条件 | 字段能力矩阵、代表场景清单、性能基线、阶段工作量估算 | 每个必需字段均标明已验证可读、需补齐或受限，并为受限项定义提示方式 |
| M1：实时基础信息 | 交付角色、Animator、状态和活动 Clip 的实时查看 | 基础 Overlay、目标选择、时间/长度/速度/Loop 展示 | 待机、移动、攻击等场景可检查，多个活动 Clip 不遗漏为单 Clip 展示，目标失效提示正确 |
| M2：混合与图调试 | 补齐混合关系、权重和 PlayableGraph 信息 | 混合详情、图概要/层级视图、来源与有效性标记 | 在选定的混合场景中可追踪 Clip 与权重所属关系，未知信息不会显示为已知值 |
| M3：记录与查看 | 将实时观测保存为可检查的会话 | 记录控制、样本与事件、会话查看、容量限制 | 能记录一段操作，按时间定位变化；切换目标、缺失和自动停止均可追踪 |
| M4：导出与稳定性 | 完成可复用的记录输出并验证长期运行 | JSON/CSV、字段说明、使用说明、验收报告 | 两种导出与会话内容一致，完成异常与性能验收，发布默认配置和已知限制 |

实时调试里程碑在 M2 完成；本轮完整交付以 M4 通过为准。记录所需的字段定义和时间语义应在 M0 明确，避免实时显示与导出含义不一致。

若核心活动 Clip 或混合信息只能覆盖部分场景，必须在能力矩阵与验收报告中列出支持范围；缺失字段的提示机制不能替代核心需求完成。

## 7. 验收场景

| 场景 | 核查要点 |
| --- | --- |
| 单 Clip 待机 | 名称、长度、时间、Loop 稳定可读，重复采样具有正确顺序 |
| 待机 → 移动 → 停止 | 观测到的状态与 Clip 变化可在记录中定位 |
| 转向或多 Clip 混合 | 同时显示参与动画及权重来源，同名多实例能够区分 |
| 攻击、技能等短动作 | 时间和进度变化合理；采样未覆盖的区间不被描述为完整过程 |
| 多层或复杂图（若场景存在） | Clip 所属关系可辨认，权重不被错误合并 |
| 角色切换与模型替换 | 跟随/固定两种模式符合约定，旧目标数据不会串入新目标 |
| 场景切换与对象销毁 | 显示失效或重新就绪，记录中留下边界和缺失信息 |
| 冻结或隐藏调试窗口 | 显示状态明确，记录按既定配置继续 |
| 开始、停止、再次记录 | 会话独立，时间、样本和停止原因正确 |
| 达到上限或导出失败 | 明确提示，已采集数据保留，可再次尝试导出 |
| JSON/CSV 一致性 | 抽查目标、样本、Clip、事件及时间，与窗口选中样本一致 |
| 长时间运行 | 达到约定时长，性能和内存有实测记录，无无界增长 |

数据正确性验收应结合可重复操作、运行时独立核查手段和记录样本进行；窗口与导出一致只能证明输出一致，不能单独证明采集值正确。无法独立核查的字段需要在报告中保留这一限制。

## 8. 完成交付清单

- 可开关的实时动画调试窗口，包含活动 Clip、混合与图信息。
- 可开始/停止、有容量边界的记录会话，以及时间列表和样本详情。
- JSON、CSV 导出及字段说明。
- 目标选择、冻结显示、记录和导出的简明使用说明。
- 字段能力矩阵、已知限制、适用版本与默认配置。
- 功能、异常场景和性能验收报告，明确通过项与尚未完成项。

本轮成功标准：使用者能够在游戏运行时确认当前动画和混合情况，并将一次操作过程记录、定位和导出，供事后检查。
